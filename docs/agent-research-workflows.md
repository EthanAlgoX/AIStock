# Agent 研究工作流

个股分析使用单一“研究策略”入口；选股区分“筛选策略”和可选的“候选深研策略”。默认选择当前市场可用的已发布完整策略，生成正式报告，不再默认委托 Agent 自行决定是否调用报告工具。目录复用策略 API 的内置配置初始化；不重复建立研究引擎。开放式自主研究仍可在主 Agent 中进行，旧任务 API 与已保存计划保持兼容。

## 策略与 Skill 的单一选择入口

- 预设研究策略展示描述和所含 Skill，只读说明研究方法，不再重复列出可勾选的 Skill。没有固定 Skill 的综合预设沿用策略默认分析方法。
- “自定义组合”仅在当前市场存在未固定 Skill 的已发布研究版本时可用。复用该正式版本，选择 1–3 个 Skill；空组合、目录未加载或读取失败时禁止运行及创建定时任务。内置 Skill 可参与单股报告生成，自定义 Prompt 用于 Agent 补充研究，不声称替换底层取数。
- 预设与自定义切换保留浏览器草稿中的自选 Skill，但预设提交 `capabilities.skillIds: []`，固定方法由正式版本提供，避免隐藏选择混入运行。自定义模式才将选择提交到原能力绑定字段。手动运行与定时任务使用同一有效绑定；不新增后端配置字段或迁移历史任务。旧任务有自选 Skill 且版本支持组合时恢复为自定义模式。
- 筛选策略负责股票池、过滤、评分和数量；候选深研策略负责筛选后的逐股报告，因此两者可以同时选择。关闭深研时不提交隐藏的深研 Skill，保留草稿供再次开启使用；默认仍仅筛选与解读。
- 交易没有额外的正式研究流程下拉框；交易逻辑与“交易策略 Skill（可选）”共同构成自定义策略，最多 3 个 Skill，用于信号研究与模拟提案，不改变确定性风险边界。
- 专家/专家团选择保持直接可见，工具、MCP、数据源按需折叠。主 Agent 会话的能力侧栏不改变。

本轮仅调整 Web 配置组织与提交绑定；回滚该前端提交并重建 Web 即可，不删除草稿或历史报告。专题没有英文对应文档，仅同步中文。

## 正式报告入口与历史归并

页面加载策略目录及各已发布版本的 `screeningPolicy.market`，仅显示匹配市场的可执行配置；优先恢复当前市场保存的版本，否则使用首个匹配版本。尚无匹配配置、目录未读取完或读取失败时，禁止启动及创建定时计划，不静默退回自主讨论，也不自动发布新策略。研究与选股页提交、转交定时任务时明确绑定策略版本和所需执行工具。选股目标与行业作为后续解读要求，实际筛选条件和候选数量仍取正式版本，不承诺自然语言条件已执行。

历史列表是报告视图，不等于原始运行台账。列表 API 追加 `primaryReportRunId`、`relatedRunIds`、`reportTitle`：只有原任务明确引用某个同类、同市场、执行时间范围内产生的正式 `agent_tool` 报告，且个股代码标准化后相同，才建立关联；多份匹配、跨股票、历史引用或无明确链接不自动合并。当前分组范围是本次列表返回的记录。前端显示正式报告入口，旧 `?run=` 链接可解析到对应正式报告，原任务解读作为相关记录折叠保留。数据库不删除、不迁移，也不按股票名称猜测归并；`/runs/:id` 仍展示原始运行，失败任务继续可追溯。

同一 Run 内正式研究报告优先呈现，`ResearchInterpretation` 默认折叠为“Agent 补充解读与待核实条件”。“待核实”用于报告中的证据缺口，不把已有正式报告替换成一整页解读对象。未真正执行的筛选显示“未生成选股报告”及原因，不能伪装为零候选成功。

交易生成约定明确使用 `TradeProposal.actions[].symbol/side`。服务端兼容已存在的 `proposals/ticker` 别名；历史 `AgentResponse` 中可识别的完整提案以只读投影视图恢复为交易报告，原始回答仍保留。报告展示操作表、参考价格、数量、仓位、进出条件、风险和证据缺口，不逐字段展开整个模型 JSON。模型 `RiskAssessment` 仅作为风险研究讨论，不采信其 `approved`、成交数字或 `PaperTradingRun` 为系统执行事实；新增运行的执行边界与零成交记录仍由服务端生成。历史恢复不触发模型调用、审批、撮合或真实交易。

## 报告优先的工作区

个股和选股首页默认显示历史报告列表及当前报告全文，配置不再占据首屏。点击“新建单股分析”或“新建选股”展开原有任务配置（市场、股票、目标、策略与 Agent 能力）；提交成功后配置收起并选中新运行，后台运行提示与历史阅读可以同时使用。列表支持按名称和股票代码搜索，包含手动、定时及 Agent 工具保存的对应类型记录；当前选择写入 URL 的 `run` 参数，便于直接打开指定报告。目录使用现有最近 100 条运行接口，不声称包含所有历史。

正式策略报告复用 `ReportSummary` 的概览、策略点位、新闻与诊断组件，并展开已有技术、基本面及风险正文。旧 Agent 报告正常渲染 Markdown 标题、表格和链接；其中可解析的 JSON 研究段按结论、证据、推断、风险和模拟情景展示。仅在原报告提供相应值时展示参考价格、估值指标与策略评分，缺失不补零，不生成虚构走势。无法解析的代码片段和原始载荷放在折叠区，运行详情使用同一研究成果渲染器。原始数据、任务合同及生成流程不变。

## 交易结果工作区

交易页面复用个股/选股的报告列表、名称搜索、URL 选中记录、详情读取和错误重试机制，范围限定为 `trading` 运行。默认不展开策略配置，也不请求策略/能力目录；点击“新建模拟运行”后按需读取最近保存的策略，仍支持保存、定时计划和模拟运行。提交成功后收起配置并选中新记录；同一页面收起后再展开保留未保存输入，离开页面后恢复的是后端已保存策略。

结果按 `TradeProposal`（模拟提案）、`RiskAssessment`（风险检查）、`PaperTradingRun`（执行记录）展示，操作数组以提案表呈现，原始内容默认折叠。`contractPassed` 只表示任务配置校验；当 `proposalRiskEvaluated` 为 false 或缺失时，明确提示尚未确认提案风险评估。真实订单数与模拟成交数只显示记录中提供的值（包括 0），不由“运行完成”推断成交，也不补造收益曲线或持仓。页面不新增任何订单接口或执行权限。停止按钮指向后台状态栏中明确标识的当前手动运行，不因查看另一份历史报告而改变取消目标。

交易仍是提案工作区，不新增账户风控、订单或成交执行权限。本专题没有对应英文版本，因此仅同步中文说明。

## 统一运行、成果与后续对话

主 Agent 是统一交互入口，研究、选股、交易是任务与成果视图，不要求每页拥有独立 Agent。确定性工作流负责正式策略的取数、计算和产物，Agent 使用 Skill、工具、MCP 与数据源进行解释或自主研究；两者不能以“模型已返回”混同为“研究目标已完成”。

- Run 的原 `status` 保持执行器语义；列表与详情追加只读 `outcome`：`pending`、`produced`、`empty`、`proposal`、`partial`、`blocked`、`unverified`、`failed`、`cancelled`。正式筛选结果为空才显示“未筛出候选”；结构化 `not_executed` 等报告显示受限，自由文本不靠关键词推断成功。最低结构检查不验证金融事实。
- 自主研究的任意文本只保存一次 `AgentResponse` 并折叠显示；明确且符合最低结构的产物才以对应类型保存。旧记录不改写：完全重复的筛选产物只显示一次；正文相同但配置不同的记录保留候选正文和可展开的独立筛选配置。兼容历史 `executionStatus` / `execution_status`。`unverified` 不等于报告不可读。
- 工作区进程内 Agent 调用正式研究工具时，同类型、同市场的成果归入当前 Run，后续解读单独保存。跨类型或跨市场调用另建 Run 并记录 `parentRunId`；独立聊天调用继续创建可回看的记录。父运行身份来自执行上下文，不接受模型或客户端指定；外部进程运行时暂未跨进程传播该上下文。
- 正式成果已保存、后续解读失败或取消时，保留成果并标识 `partial`。交易产物只显示“提案已生成”，不代表账户风控通过或下单。
- 报告和运行详情提供“继续问 Agent”，载入已有报告摘录、来源 Run 与结果状态，不自动发送、不自动重新运行。摘录总上限为 24,000 字符，标明截断；切换会话或新建会话会丢弃迟到的上下文。后续是否调用工具仍按用户请求和 Agent 能力授权执行。
- 用户聊天列表在分页前排除保留的 `workspace-` 内部会话命名空间；内部记录不删除，不影响运行追溯。

个股、选股和交易仍以报告为首页；新任务中，研究策略与专家协作是主要配置，不再藏在“高级能力配置”弹窗。Skill 的唯一选择位置是自定义策略组合区，预设策略显示所含方法。工具、MCP 和数据源保留页内折叠，能力目录失败可直接重试；主 Agent 会话侧栏保持原交互。市场页面优先展示行情与研究，订阅及数据源同步详情后置，来源详情默认折叠。数据配置状态不冒充实际覆盖验证。

## 专家与运行阶段的边界

当前专家团协议为“独立意见 → 主持汇总”，没有多轮交叉质询。页面取消轮次数设置；旧配置仍保留在历史快照中，但运行提示不使用旧轮次数。团队协议文字是备注，不控制执行器阶段；专家可以使用各自工具，因此共享任务输入不等于每位专家读取了完全相同的数据快照。

运行在 `resultSummary.stages` 保存实际工作流、Agent、各专家及主持调用的开始/结束状态。页面可展开查看，不显示虚构百分比；“调用结束”不等于业务成功。历史运行没有阶段记录时不补造。服务重启将未结束运行及其活动阶段标记中断，不支持断点续算。持久化 worker、阶段级重试、统一预算以及逐项证据来源规范属于后续改造，不在本轮中承诺。

内置全市场扫描的支持市场复用筛选引擎声明（当前为 A 股、美股）；任务显式绑定该工具且没有正式策略版本时，启动前拒绝不支持的市场，避免消耗模型调用后才发现能力不匹配。

## 执行与能力

- 主 Agent 默认能力新增 `list_research_workflows`、`run_stock_research`、`run_stock_screening`。旧会话保存过能力选择时，需要在能力面板启用新工具。
- 主 Agent 工具执行成功后，同样保存到任务与运行台账，返回 `reportUrl` 供聊天回答链接完整报告。该单次任务默认停用，不自动调度。后续对话可解释已返回的结果。
- 发现工具只读取正式配置，不创建或发布策略。执行工具调用 `StrategyKernelExecutorService.execute_product`，拒绝草稿、裸内核和错误用途。单股工具沿用股票范围检查。
- 任务页选择策略后，将正整数 `config.strategyVersionId` 保存到任务；研究/选股任务必须授权对应执行工具。运行和定时任务保持版本绑定，不能通过自然语言改写冻结参数。
- 先执行内核并保存 `ResearchReport` 或 `CandidateList`，再由 Agent 解读。绑定专家时，每位专家收到同一份原始结果；主持人保留分歧。解读保存为 `ResearchInterpretation`，不覆盖原始成果。解读阶段移除工作流和全市场扫描工具，避免重复扫描。
- 工作流失败不会生成成功成果。解读或专家阶段失败时，本次运行失败，但已经保存的原始策略成果可以在运行详情查看。取消在执行前后检查；内核内部网络请求不保证立即中断，已写入的分析历史仍然保留。

## 数据与报告

单股内核复用行情、技术计算、新闻与基本面准备，以及现有 LLM/Agent 报告流水线。内核参数 `decisionPolicy.packageParameters.analysisMode` 默认为 `standard`，使用确定性证据准备和一次综合 LLM 报告；`agent` 显式使用内部 Agent 分析。该覆盖仅复制本次请求配置，不修改全局主 Agent 设置。任务级专家评审在报告之后按需执行。

其当前数据访问仍使用平台统一路由；任务选择的 MCP 用于后续 Agent/专家补充证据，不会替换内核取数。不能把任务的 MCP 选择视为内核提供方锁定。覆盖字段 `configured` 表示配置声明，`available: null` 表示未在适配层独立验证，请读取报告 `diagnostic_summary`。`evidenceRefs` 的分析历史引用用于追溯报告，不冒充逐条新闻来源。选股内核也将覆盖声明与实际抓取分开，实际来源、过滤统计及降级记录见选股结果；返回的筛选历史引用用于回看同次扫描。

选股复用市场快照、硬过滤、代码因子评分、可选 LLM 重排和风险处理。市场、参数与候选数量由正式策略决定；任务页自然语言目标及行业要求仅作为解读要求，尚未被该策略验证的条件必须列为待核实，不能声称已经完成过滤。

任务页面及运行详情复用现有单股报告组件；候选表保留真实股票代码、评分、依据与风险，零分不视为缺失。旧自由文本成果仍能显示。原始 JSON、警告和策略版本可展开查看。

## 验证与回退

### 页面切换与后台运行

个股、选股、模拟交易和专家评审的 Run 由后端执行，不依赖当前页面是否打开。前端共享运行状态与尚未完成的提交请求，离开页面只清理页面轮询，不取消或重新提交任务。返回页面立即校准同一 Run 的状态；刷新浏览器后，从对应类型最近 100 条记录中优先恢复仍在排队/运行的手动任务，否则展示最新手动任务及其成果。定时任务与主 Agent 工具产生的记录不会替换这几个页面的手动任务，它们仍可从“任务与运行”进入。

提交与恢复状态期间禁用重复启动；可见页面每 1.5 秒查询进行中的运行，短暂失败会提示并自动重试，不丢弃最后一次已知状态。完成、失败和取消均以服务端状态为准，终态停止轮询。模拟交易的停止按钮仅发送取消请求，不提前展示“已停止”；耗时根据服务端开始/完成时间计算，不因切页归零。浏览器关闭后，只要服务端进程仍在运行，任务会继续；服务端重启后的处理仍遵循现有运行中断机制，并不支持计算断点续跑。

个股与选股保留各自的表单草稿，恢复时可从任务快照重建股票、条件和策略版本；运行摘要使用冻结的任务名称，不会随当前草稿修改。专家评审恢复对应的议题与模式。页面提供本次运行详情入口，历史记录不删除。

回归覆盖真实策略目录、正式内核执行边界、错误用途/市场、股票范围、工具授权、原始成果保存与解读隔离、前端版本提交和候选展示。离线测试替换外部行情/LLM服务，不证明在线来源或投资结论有效。

无需新增环境变量或数据库迁移；API 追加结果状态、阶段和报告关联元数据。回退应恢复本批前后端改动、重建 Web 并重启服务，保留数据库；历史记录不会删除或迁移。自主研究从主 Agent 进入，不自动获得正式策略验证标识；已有未绑定版本的定时任务不会被本次页面改造静默改写，需要用户重新配置后才使用正式报告流程。没有直接对应英文专题文档，本次仅同步中文说明；未改变中英运行引擎协议文档所述的传输协议。
## 研究方法、候选深研与信号复盘

单股正式配置包含原综合研究及成长质量、事件驱动、趋势量价、预期重估四种方法。方法复用 `strategies/*.yaml`，通过正式版本的 `decisionPolicy.packageParameters.skills` 传入 `AnalysisService`，参与报告生成而不只是末端点评。专用配置以版本中保存的 Skill 为准；综合配置可接收任务中选择的内置 Skill。自定义说明与 MCP 仍用于主 Agent 的授权补充研究，不声称已经注入底层平台数据流水线。未知 Skill 拒绝执行，不静默换成默认研究。

选股任务可配置 `deepResearchCount`（整数 0–3，默认 0）及 `deepResearchVersionId`。非零时必须绑定同市场已发布可执行单股配置并启用 `run_stock_research`。按照筛选结果原顺序去重后研究前 N 只；不按模型自由提议扩展股票池。每份完整报告以 `CandidateResearch` 保存到原 Run，候选研究失败不删除筛选报告，业务成果显示部分产出。取消后不再启动下一只；在途模型调用仍受原执行器的取消/超时能力限制。主 Agent 收到有界逐股摘录，比较研究优先级但不能改写原始排名。手动任务和定时任务共享这些配置与预算，默认不增加模型调用。

交易页的“信号跟踪与复盘”读取最近 20 条已有 `DecisionSignal`，展示来源报告编号、有效期、风险、计划价位和既有评估。用户可保存基于原报告快照的保守/均衡/激进偏好重评，或更新选中信号的 1/3/5/10 日后验评估。窗口不足和行情缺失必须显示无法评估；不是策略胜率保证、账户回测或风控批准。自由文本 `TradeProposal` 不自动转换成已验证信号。工具 `get_stock_decision_review` 只读取指定股票最近 5 条信号及已保存的评估，须按既有能力配置授权，不创建信号或订单。当前未新增自动到期评估调度，更新评估由用户显式触发。

专家仍先独立研究；只有规范方向枚举形成买卖对立且双方置信度至少 0.7 时，既有 `ConflictDetector` 才触发一次主持证据复核。无效枚举、缺失置信度、低置信度或同向意见不触发额外调用。原意见不覆盖，复核失败和未解决分歧保留给最终汇总；不声称完成了多轮交叉质询，也不将文本结论视为账户风控事实。

### 内置选股规则

选股页面通过正式策略版本选择内置规则：双低（保留原“多因子选股 · A股配置”）、均衡多因子、蓝筹收益质量、资金热度、低波质量、趋势质量、超跌反转、稳健价值、缩量回踩、放量突破。规则来自 `src/services/screening/strategies/`，与参考 daily_stock_analysis 的 10 套 YAML 相同，不另建平行筛选实现。

系统初始化为其建立独立、不可变的运行配置；复用原选股 Python 内核和 Agent 工具。既有双低版本及数量保留，其余配置使用规则的默认输出数量；重复初始化不新建版本，归档配置不自动恢复，同名用户配置不覆盖。目前这组内置规则仅支持 A 股，不据此开放港股或美股。

执行仍是：真实数据快照 → 硬过滤 → 因子计算 → 可选 LLM 候选池内重排 → 风险与组合约束 → 主 Agent/所选专家解读。自然语言目标不暗中改写冻结规则；MCP 用于授权范围内补充证据，不绕过数据源与工具权限。

报告保留实际候选排名，增加按股展开的研究依据、因子明细、催化因素、观察项和失效条件，以及组合风险和数据降级说明。只展示本次返回的证据；缺失因子不补零，缺失风险不等于安全；旧报告不重新调用模型，也不补造历史分析。因子评分不是收益预测，候选不是交易指令。
