# 策略实验室：二次开发规划与进度

更新时间：2026-08-10

## 产品定位

AI Stock 的核心不是单次问股或报告生成，而是把既有股票分析、选股和 Agent Skill 组织成可配置、可复跑、可评估的多 Agent 模拟交易策略。用户先用历史或模拟数据验证策略，再决定是否手动跟随交易计划；系统不会替用户下真实订单。

## 已有资产

- 分析编排：快速、标准、完整、专家协作四种工作流，覆盖技术分析、情报、风险和决策。
- 策略资产：`strategies/` 中的 16 个分析 Skill，以及 `src/services/screening/strategies/` 中的 10 个选股策略。
- 结果资产：分析历史、选股历史、决策信号及其后验结果。

这些资产将被复用为策略的候选池、专业 Agent 和评估输入；它们不会被模拟交易功能改写。

## 策略继承原则

默认优先使用原项目已经验证、可解释且有来源文件的策略资产，而不是让用户从空白 Agent 画布开始配置。

- **官方策略模板库**：将选股策略、分析 Skill 与编排模式组合成开箱即用的多 Agent 模板；每个模板保留原始策略 ID、来源文件、推荐输入和风险边界。
- **分层复用**：选股策略负责候选池，分析 Skill 作为专家 Agent，快速/标准/完整/专家协作链路决定编排深度；三层都可独立替换或组合。
- **渐进式自定义**：用户先复制官方模板，再修改数据源、Skill 组合、Prompt、风控和仓位规则；任何修改都生成新版本，不覆盖官方模板或历史运行。
- **真实性约束**：模板的“有效性”仍要经过本系统的模拟运行样本验证；继承原策略不等于自动标记为可跟随。

## 安全边界

- 模拟交易与真实持仓、告警、回测、券商连接分别存储，默认无读写耦合。
- 任何“跟随”只导出人工复核的交易计划，不创建真实订单。
- 策略有效性只基于已保存的模拟运行、成交和后验评估数据；样例和本地预览不得显示为真实收益。

## 交付方式：页面优先的纵向切片

后续不再先把某一阶段的后端能力全部完成后才展示页面。每个阶段先交付一个可浏览、可操作、能表达真实状态边界的页面切片，用户确认信息架构和交互后，再逐项接通后端。

1. 先做页面结构、空状态、预览状态和交互入口；未接通的数据必须显示为“待接入/预览”，不能伪装为真实结果。
2. 用户确认页面效果后，按最小闭环接入一个真实能力（例如账户创建，再到订单，再到成交）。
3. 每接通一项都保留失败、加载、无数据和隔离边界，并立即部署到 Docker 供复查。
4. 未确认的页面结构不进行大规模底层开发，避免后续推翻信息架构时重做账本或运行时。

## 分阶段计划

| 阶段 | 目标 | 交付与验收 | 状态 |
| --- | --- | --- | --- |
| P0 | 建立策略优先的信息架构 | 默认显示模拟交易入口；预置策略、Agent 链路、数据源和只读关联可见 | 已完成 |
| P1 | 建立策略实验的可追溯底座 | 策略定义、不可变版本、模拟运行记录及 API；所有记录标注为模拟且不触及实盘资产 | 已完成 |
| P2 | 官方策略模板目录 | 把原项目的选股策略、分析 Skill 和四种编排链路登记为可追溯、可复制的模板；展示来源与默认风控 | 已完成 |
| P3 | 策略编辑与版本治理 | 从模板复制个人策略；可编辑数据源、Skill、Prompt、风控、仓位规则；每次保存生成不可变版本 | 已完成 |
| P4 | 多 Agent 模拟运行时 | 用策略版本调用既有编排；保存输入快照、每个 Agent 的 Prompt/输入/输出、候选池、决策和反思事件 | 待开始 |
| P5 | 纸面执行账本 | 为已完成运行生成模拟订单、持仓、现金、费用、滑点和权益曲线；可按运行回放 | 待开始 |
| P6 | 策略有效性评估 | 基于纸面账本与后验结果计算样本量、收益、回撤、胜率和失效原因；首页统一显示验证状态 | 待开始 |
| P7 | 人工跟随工作流 | 仅向已满足门槛的策略导出人工复核交易计划、风险检查与仓位建议；始终不自动下单 | 待开始 |

## 当前进度

### 已完成

- 新增“模拟交易”作为默认侧边栏页面，不受选股开关控制。
- 建立三套预置组合，并把选股策略与 Agent Skill 映射为可见的策略编排。
- 首页新增“预置策略有效性”入口，模拟页可只读查看选股、观察列表和分析历史的关联摘要。
- 修正预览语义：未接入数据源不可选；运行、输入和账本均明确为本地预览、尚未保存。

### 已完成（策略资产化）

- 建立策略定义、版本和模拟运行的后端持久化与 API。
- 在 Docker 服务中完成建表及“创建策略 → 创建版本 → 创建模拟运行”的链路验证；测试记录已清理。
- 模拟交易页面已接入策略实验 API：预置策略会保存为版本快照，并创建 `queued` 的预览运行记录。
- 首批六套官方模板已登记原项目来源资产与默认风控：趋势突破、回踩质量、题材催化、质量价值、超跌修复、红利防御。
- 官方模板已迁移到后端受版本控制的目录；页面优先读取该目录，保留来源文件与推荐输入。
- 用户可复制模板建立个人策略 v1，编辑名称、说明、Skill、编排、风险、仓位和各 Agent Prompt，保存时生成 v2+；策略元信息和历史版本均可读取。

### 下一步

当前优先交付 **P5 纸面账户工作台页面预览**：展示账户概览、运行回放、订单、持仓、权益曲线和拒绝原因的空/预览状态；用户确认后，再分步接入账户创建、订单、成交、持仓和权益快照。P4 运行时与 P5 账本后端继续按最小闭环接线，不再等待全量完成。

## 阶段依赖与验收顺序

```text
官方模板（P2） → 可编辑策略版本（P3） → 可复跑 Agent 运行（P4）
                                      ↓
                            纸面订单与权益账本（P5）
                                      ↓
                              有效性评估（P6）
                                      ↓
                              人工跟随计划（P7）
```

每阶段只消费前一阶段的可信记录：P4 不伪造执行结果，P5 不从 UI 样例生成订单，P6 不用不足样本输出“有效”，P7 不创建或提交真实交易。
