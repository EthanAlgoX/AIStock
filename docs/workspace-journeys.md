# 工作区功能串联与运行记录

## 从问题到后续操作

- 个股研究：输入明确股票代码并确认市场，查看默认方案后再运行。报告仍保存一次；持仓研究复用同一份研究运行。
- 股票档案：个股研究页面可按代码查看研究、结构化关联的专家讨论、选股候选深研。候选表可直接打开档案，再选择是否运行研究。旧讨论若没有股票代码，不从文字猜测股票归属。
- 专家讨论：个股议题填写关联股票代码，服务端核对代码与市场。宏观议题可留空。从报告发起讨论时继承原报告上下文。
- 选股：所选正式策略版本决定市场、筛选规则、排序和数量。自然语言及行业关注点仅用于解读，不自动成为筛选条件。
- 交易提案：明确选择同市场、已完成的选股结果，或本人自选股、持仓。启动前解析并冻结实际股票代码、来源运行和来源日期；空来源不进入执行队列。从选股运行详情可带入该来源。
- 历史研究提案入口（`/trading?view=reports`）生成研究提案，仅校验风险参数范围；尚无账户级提案风险评估、订单审批、模拟撮合或真实成交。历史候选日期不代表最新行情。定时任务每次解析来源并分别冻结，指定选股报告不会自动替换为最新报告。

- 策略运行：`/trading` 支持独立回测与每日持续模拟，记录真实数据驱动的模拟买卖、持仓与观点。每次检查进入任务与运行，详情双向跳转；与研究提案分开。见 [策略验证与运行](strategy-portfolios.md)。

## 任务与运行

`GET /api/v1/workspace/run-history` 返回 `items / total / statusCounts / offset / limit`。支持 `kind / status / query / stock / market / start / end`；默认每页 30 条，上限 100。日期边界按 UTC、结束日期包含当日。总数及状态计数来自同一筛选范围的数据库查询，不受当前页限制。旧 `/runs` 数组接口保留兼容。

普通研究、持仓研究、选股、交易、专家讨论仍使用原工作区执行器。大盘复盘沿用原后台队列，聊天正式工作流沿用策略执行器，但执行前登记运行，运行中和失败均可查询；不为普通短问答额外创建任务。兼容以前的市场复盘任务 ID、历史报告及通知逻辑。已有未登记的旧市场任务不会回填为虚构运行。

运行详情显示来源、结构化关联股票、直接归属于该运行的 Token 与调用次数。成员使用原额度调用账本，管理员使用原模型用量表；不重复计费。显示估算量，无可归属记录不表示零消耗。独立子运行在自己的详情记账，父运行不重复累加。

工作区任务可停止；重新运行会新建任务及运行，重新校验能力和来源、产生新消耗，旧记录不变。外部队列运行暂不提供工作区停止或重跑按钮，避免显示已停止但实际仍在执行。暂停定时计划与停止当前运行是不同操作。

## 价格告警与部署

Web 拥有调度权时，`--serve-only` 也会启动独立价格轮询线程，但不会因此开启每日模型调度。外部 CLI 拥有调度权时仍不在 Web 重复启动。是否真正检查仍受原告警开关控制，界面同时检查轮询与通知渠道；保存规则不表示已经具备投递条件。

新用户首次并发打开目录时，专家初始化使用独立保存点处理重复插入，不覆盖已有自定义配置。

工作区串联复用现有任务、成果和计量表；策略账户另由数据库初始化创建运行控制表，无需新配置。服务器继续使用原启动命令、私有工作区、数据目录和 SSH 授权。发布前备份源文件、容器配置和数据库，保留旧镜像/容器；回滚容器保留数据，不删除新运行记录。

## 验收边界

自动验证覆盖分页、筛选、数据库隔离、空/错误候选来源、失败任务留档、运行归属计量和 serve-only 生命周期。构建不等同于真实模型或通知投递验证；部署后另查 HTTPS、认证接口及实际页面。当前没有对历史自由文本进行股票推断、自动补写对话、接入真实交易或改造全部计划配置。
